Agent Tuneup
Configuration flags and options for fine-tuning agent behaviour
Inherit skills YAML flag

Agents don't inherit skills by default. Use the skills flag to pass specific skills into an agent.

skills:
    - code-reviewer
Effort & model YAML flag

Control how much compute the agent uses and which model it runs on.

effort: low | medium | high
model: haiku
Always run in background YAML flag

Set background: true so the agent always runs without blocking your session.

background: true
Isolated worktree YAML flag

Runs the agent in a separate git worktree — useful for experimental refactors that shouldn't touch your working branch.

isolation: worktree
/insights command Command

Use /insights inside Claude to find out where you are lacking — it surfaces usage patterns and suggestions to improve how you're working with Claude.

Launch a specific agent directly CLI flag

Start Claude pre-loaded with a named sub-agent so it doesn't have to be loaded on every invocation.

claude --agent <subagent-name>
Hooks inside an agent YAML flag

You can define hooks directly inside an agent's config — for example, to run a shell command whenever a specific tool is used.

hooks:
    PostToolUse:
        - matcher: "Read"
          hooks:
            - type: "command"
              command: "echo 'Read tool was used'"

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node -e \"try { const cmd = JSON.parse(require('fs').readFileSync(0, 'utf-8')).tool_input.command; const patterns = ['rm -rf /', 'rm -rf ~', 'drop table', 'truncate', '--force', 'push.*--force']; const match = patterns.find(p => new RegExp(p, 'i').test(cmd)); if (match) { console.error(`Blocked: pattern '${match}' detected`); process.exit(2); } } catch (e) { console.error(`Hook Error: ${e.message}`); process.exit(1); }\""
          }
        ]
      }
    ]
  }
}
settings.json 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",

  }

MCP Server
Connect Claude to external tools and data sources via Model Context Protocol
What is MCP?

MCP (Model Context Protocol) is an open standard that lets Claude connect to external tools, data sources, and services. Think of MCP servers as plugins for Claude — each server exposes tools Claude can call just like any built-in tool.

MCP servers are configured in a .mcp.json file at the project root. Claude Code reads this on startup.

Hands-on — Memory MCP Server
① Create .mcp.json — ask Claude
paste into Claude

Create a .mcp.json file in the project root with the memory MCP server configured. Use npx to run @modelcontextprotocol/server-memory and store the memory file at .memory/memory_doctor_patient.jsonl

Or create it manually
.mcp.json 
{
  "mcpServers": {
    "memory": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-memory"
      ]
    }
  }
}
Or with a custom memory file path
.mcp.json 
{
  "mcpServers": {
    "memory": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-memory"
      ],
      "env": {
        "MEMORY_FILE_PATH": "/path/to/custom/memory.jsonl"
      }
    }
  }
}
② Restart Claude Code, then verify

/mcp

Claude Commands
Built-in commands for remote control, scheduling, and session automation
dispatch COMMAND

Assign tasks to Claude from anywhere using the Cowork environment. Message Claude from your phone to trigger real work on your active desktop — Claude uses your local files, desktop apps, and connected plugins, then sends a push notification with the result when done.

Provides a single continuous persistent thread across mobile and desktop.

remote COMMAND

Continue a local Claude Code session from any device. Connects a web interface at claude.ai/code or the Claude mobile app to your machine's running session — Claude executes tasks locally with full access to your filesystem, MCP servers, and tools.

claude remote-control
# or inside Claude:
/remote-control
schedule COMMAND

Set up and manage recurring tasks. Runs persistently in Anthropic's cloud infrastructure (even when your computer is off) or on your local machine via Desktop scheduled tasks.

/schedule

Use cases: reviewing PRs every morning, checking CI failures, writing documentation summaries.

loop COMMAND

A bundled skill for scheduling a recurring prompt within your current session. Provide an interval and prompt — Claude repeats it for as long as your session stays running. Lightweight alternative to fully persistent scheduled tasks.

/loop 10m check if the deployment finished
