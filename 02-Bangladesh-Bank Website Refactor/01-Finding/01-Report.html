Executive Summary

The Bangladesh Bank homepage (bb.org.bd/en/) serves as the primary digital gateway for one of South Asia's most important central banks. While the site successfully consolidates a very large amount of financial, policy, and regulatory content into a single page, the current refactoring exposes critical weaknesses in accessibility, visual hierarchy, cognitive load management, and mobile responsiveness — issues that directly harm the experience for citizens, banking professionals, and international stakeholders alike.

The most urgent concerns are a severe dual-navigation architecture that creates redundancy and confusion, a hero section that mixes Bangla and English content without clear structure, extremely small navigation link tap targets, and a page-width layout that is clearly designed only for desktop screens. The right-column sidebar, while useful in concept, suffers from inconsistent heading styles — at least two headings appear to be constructed from horizontal rule characters (__________________________) rather than meaningful text, indicating incomplete templating or copy-paste errors in the refactoring.

On the positive side, the site demonstrates good intent with a consistent green/teal brand palette, quick-access financial data widgets in the sidebar (policy rates, exchange rates, call money rate), and a "Recent News" ticker that keeps content fresh. With focused remediation of the critical issues below, the overall UX quality can be elevated substantially.

Identified Issues
1
Dual Navigation Architecture — Redundant & Contradictory Menus
Critical
UsabilityNavigationCognitive Load

The page contains two completely separate navigation systems: a hamburger-driven side drawer (ref_1 – ref_156) and a separate horizontal top navigation bar (ref_173 – ref_339) that is visually layered on the hero banner. These menus have overlapping but not identical content. For example, the side menu includes Media & Press Release and Financial Stability as top-level items, while the horizontal nav does not expose them at the same level. A first-time user cannot predict which menu is authoritative.

Additionally, the horizontal top nav is styled with very small, white-on-green text positioned at the very bottom edge of the hero banner image, making it visually secondary yet functionally primary — a direct contradiction of user expectations.

2
Broken / Garbage Heading Text in Right Sidebar
Critical
Visual HierarchyContent QualityAccessibility

At least three heading elements (ref_607, ref_613, ref_618) in the right sidebar contain raw underscore/dash characters ("__________________________" and "__________________________Call Money Rate") as their text content instead of meaningful section titles. These appear to be CSS-divider hacks implemented via heading tags. This is both a semantic HTML failure (misuse of heading hierarchy) and a visual defect — screen readers will announce these as headings, severely degrading the experience for assistive technology users.

3
Hero Banner: Mixed-Language Content With No Visual Separation
Critical
UsabilityVisual HierarchyCognitive Load

The hero/carousel section immediately below the header renders dense Bangla script notice text at a very small font size (~11–12px estimated) inside the carousel slide, alongside a small standalone notice box with even smaller Bangla text. There is no clear visual language indicating what type of content this is (alert? news? policy?), how many slides exist, or a meaningful slide title in the language of the current UI (English is selected).

Furthermore, the Governor widget (right panel) uses ALL-CAPS "HONORABLE GOVERNOR" as a section label in a bright green bar, then places a photo and name below — with no clear visual divider between this decorative widget and the carousel slides. The two regions compete for the user's attention with equal visual weight.

4
Extremely Small Navigation Link Tap Targets (< 24px height)
High
AccessibilityResponsivenessMobile UX

The horizontal navigation links (ABOUT US, MONETARY POLICY, FINANCIAL SYSTEM, FX MARKET, G-SEC MARKET, PUBLICATION) are rendered at a very compressed height positioned at the bottom edge of the hero image. Their estimated tap target height is well below the WCAG 2.5.5 recommended minimum of 44×44 CSS pixels, and the AAA-recommended 44px touch target. On touch devices, users will frequently mis-tap, activating the wrong menu item or missing entirely.

5
Inconsistent Card Header Color Coding (Green vs. Red Border-Left)
High
Visual HierarchyConsistency

The content cards in the main two-column grid use two different left-border accent colors with no apparent semantic rule: some cards (Monetary Policy, Investment Facility, G-SEC Market, Links, Innovation Corner, Citizen Charter, National ICT Policy, Services, Recent Upload) have a green left accent, while others (Media & Press Release, Economic Data, Payment Systems, Financial Stability, National Integrity Strategy) have a red left accent. There is no legend or visual cue explaining what green vs. red signifies, leaving users to wonder if red cards carry urgent or warning content.

8
Inline Pipe Separators Used as Navigation Elements (Anti-Pattern)
Medium
UsabilityAccessibilityConsistency

Several content areas use raw pipe characters (|) as visual separators between hyperlinks within a single list item — for example "Prizebond | Sanchayapatra" (ref_420–422), "G-Sec OMS | YTM Curve | MTM" (ref_440–443), "E-Tender | E-Recruitment" (ref_466–468), and others. This is an anti-pattern: the pipe character has no semantic meaning in HTML and is not announced by screen readers, making the relationship between the grouped links ambiguous. It also creates very small click/touch gaps between adjacent interactive elements.

Information Overload: 14+ Content Sections on a Single Homepage
Medium
Cognitive LoadUsability

The homepage simultaneously presents: Monetary Policy, Media & Press Release, Investment Facility, Economic Data, G-SEC Market, Payment Systems, Links, Financial Stability, Innovation Corner, National Integrity Strategy, Citizen Charter, National ICT Policy, Services, and Recent Upload — plus a sidebar with Policy Rates, Reserve Ratios, Exchange Rate, Call Money Rate, MMRR, Auction Calendar, Emergency Hotline, ICT Security Alert, and CIPC — totaling over 23 distinct content modules. For a first-time user, there is no clear path or priority — every section competes with equal visual weight and the page scrolls to a very significant length.

Decorative Card Icons Have No Alt Text Suppression
Medium
Accessibility

Alert/banner images in the hero carousel (ref_342–350: "Alert", "Alert", "Alert", "Alert", "BB logo usage alert", "Offshore Banking Law Feature", "Special Notice", "Cautionary Notice", "FEPD Notice") have alt text set to their generic names rather than meaningful descriptions. Purely decorative images should use alt="" to be skipped by screen readers. Images that are informative (e.g., alert notices) require detailed alt text describing their content — using single-word labels like "Alert" is insufficient for users who cannot see the image.

11
Relative Path URLs Risk Broken Links Across Subpaths
Low
Code QualityUsability

Multiple links throughout the page use deeply nested relative paths (e.g., "../../../../../econdata/nsdp/nsdp_bb.php", "../../../../mediaroom/circulars/..."). These relative paths are fragile: they will break if the page is served from a different directory depth, embedded in another context, or if the URL structure changes. They are also difficult to maintain. The site mixes absolute paths (/en/index.php/...) and relative paths inconsistently, indicating an incomplete refactoring.

Fig 11.1 — Inconsistent URL strategy mixing relative and absolute paths

12
"New" Badge Uses Inline Red Box with No ARIA Context
Low
AccessibilityVisual Hierarchy

The "New" badges applied to certain links (ref_391 on MPS January-June, 2026; ref_396 on MPC Resolution) are rendered as styled <generic> (likely <span>) elements inside the link. While visually useful, they carry no aria-label addition to the parent link — a screen reader user hears "MPS (January-June, 2026) New" as a run-on string, which may be confusing. Additionally the badges are small red-background boxes that need checking against color-contrast requirements for the white text within.

Proposed Improvements

Fix #1 — Consolidate to a Single, Unified Navigation System

Eliminate the dual navigation architecture. Choose one canonical navigation pattern — a top horizontal mega-menu is appropriate for a content-rich government site — and remove the redundant hamburger sidebar on desktop. On mobile, the hamburger should trigger the same unified menu. Ensure all nav items are present in both variants with identical hierarchy. Conduct an IA (Information Architecture) audit to merge the "Media & Press Release" and "Financial Stability" top-level items currently missing from the horizontal nav.

Fix #2 — Replace Decorative-Divider Headings with Proper HR Elements

Remove all heading elements whose text content is only underscores or dashes. Replace them with a styled <hr> element for visual separation, or with a proper <h3> or <h4> with a meaningful title (e.g., "Financial Market Rates"). Update the CSS to style the <hr> as needed. Ensure the heading hierarchy (h1 → h2 → h3) is logical and non-skipping throughout the page.

<!-- Before (broken) -->
<h2>__________________________</h2>

<!-- After (correct) -->
<hr aria-hidden="true" class="sidebar-divider" />
<h3>Financial Market Rates</h3>

Fix #3 — Redesign the Hero Section with Clear Language & Content Hierarchy

Separate the notice/alert carousel from the static Governor widget using a clear visual gap or background color distinction. Set carousel slides to display their title in both Bangla and English (or respect the language toggle). Increase the minimum font size of carousel body text to at least 14px. Add numbered slide indicators (e.g., "3 / 9") so users understand the carousel size. Ensure each slide has a clear heading-level title.

Fix #4 — Increase Navigation Link Touch Targets to ≥ 44px

Apply sufficient vertical padding to all top navigation links. Move the horizontal nav bar above (or below) the hero image as a distinct strip — do not overlay it on the banner. Ensure each link has a minimum height of 44px and horizontal padding of at least 12px on each side to meet WCAG 2.5.5 (AA) and Google's touch-target guidelines.

/* Recommended minimum */
.nav-link {
  display: inline-flex;
  align-items: center;
  min-height: 44px;
  padding: 0 16px;
  font-size: 14px;
}

Fix #5 — Define a Semantic Color System for Section Cards

Establish a documented color rule for the card left-border accents. Recommendation: use a single brand green for all standard content cards. Reserve the red accent exclusively for urgent/alert sections (e.g., ICT Security Alert). Add a brief visual legend or tooltip if multiple colors are retained. Update the CSS custom properties (or SCSS variables) to enforce this system-wide so future cards default to the correct color.
