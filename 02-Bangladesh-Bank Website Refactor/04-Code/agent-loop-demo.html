    The loop every checkpoint runs

    Each role is a separate subagent with fresh context. It sees only files and reports, never another role's reasoning.

    goal.md + plan.md → brief.md listing every file and step.

    2 · red

    Test

    Tester

    Writes tests from test-criteria.md before the code exists and proves they fail.

    3 · green

    Code

    Developer

    4

    Review + Visual QA

    ↺ FAIL sends findings back to the Developer · max 3 rounds, then ⛔ blocked and ask the human

    Orchestrator

    main session
    Does
    Schedules checkpoints, creates worktrees, starts subagents, updates PROGRESS.md, writes the HTML report, asks for approval
    Never
    Writes application code or tests

    Planner

    Plan / architect-planner
    Does
    Turns plan.md + goal.md into a short brief: files, steps, design line ranges
    Never
    Writes code

    Tester

    independent-tester
    Does
    Writes the tests from test-criteria.md first and proves they fail (red)
    Never
    Reads the developer's code or reasoning; weakens a test

    Developer

    section-porter / developer
    Does
    Writes code until every test is green, inside its own worktree
    Never
    Edits a test to make it pass

    Reviewer

    design-fidelity + adversarial
    Does
    Reviews the diff and runs visual QA with Chrome DevTools MCP against the prototype
    Never
    Fixes code itself

    Why independence matters: the Tester never sees the code it judges, and the Reviewer never fixes what it finds. Nobody grades their own homework.

    Git worktreesEach checkpoint gets .worktrees/cpNN on branch migration/cpNN-<name>. Parallel agents never touch the same files.
    8 waves, max 3 parallelA checkpoint starts as soon as all its dependencies are merged.
    Human gatesBefore any install · before every merge (one approval per wave) · open decisions · blocked checkpoints.
    Never advance on redNever skip a step. Never edit a test to make it pass.
