01 — Guiding principles

Seven rules every checkpoint obeys

When a Nuxt convention conflicts with pixel fidelity, fidelity wins. Accessibility additions are invisible additions.

01

The prototype is the specification

Colors, spacing, fonts, radii, shadows, copy (en + bn), hover states and transitions are transcribed exactly.

02

Keep the data-driven pattern

Locale dictionary → typed props → simple components.

03

One responsibility per file

A repeated item becomes its own component.

04

Every audit issue maps to a checkpoint

No issue is left without an owner and a verification step.

05

Each checkpoint ends demo-able

Buildable, testable, demo-able. Never advance on red.

06

SSG only

ssr: true, nitro.preset: 'static'. No backend, no server routes, no runtime fetch.

07

Invisible accessibility

aria-*, landmarks, skip link, tel: links and focus styles without changing a default-state pixel (D1).

    07 — Risks and decisions

    Three decisions made up front, seven risks watched

    Decisions settle the tension between pixel fidelity and accessibility. Risks each carry a concrete mitigation, not a hope.

    Decisions D1–D3

    • D1

      Fidelity vs accessibility: the prototype has no ARIA, skip link or tel:

      Impact: audit fixes need markup the design lacks.

      Add semantic and ARIA markup that does not change a default-state pixel. Skip link is visually hidden until focus.

    • D2

      The prototype has 0 @media rules

      Impact: mobile layout undefined.

      CP11 adds breakpoints at 768 px and 375 px; desktop (1280 px) stays pixel-exact.

    • D3

      Ticker pause control is a new visible element

      Impact: small visual change.

      Approved exception for WCAG 2.2.2; style it with existing tokens.

    Risks R1–R7

    • R1

      Bangla transcription errors

      Impact: wrong official content.

      Copy text programmatically from the T dict; key-parity test; native-speaker review in CP11.

    • R2

      to: null nav links (about, fx, gsec, pay)

      Impact: dead links confuse users.

      Keep non-navigating (faithful) and mark aria-disabled="true"; list for a later phase.

    • R3

      support.js / image-slot.js are design runtime

      Impact: accidental port of tool code.

      Do not port. check-port.mjs hook flags sc-for, sc-if, style-hover.

    • R4

      Visual diff by eye is subjective

      Impact: missed deltas.

      Fixed widths (1280 / 768 / 375) and a written per-section checklist in each test-criteria.md.

    • R5

      The prototype fails WCAG 1.4.3 twice: #9aa39e on white is 2.59:1 (8 uses), white on #F42A41 is 4.00:1

      Impact: fidelity conflicts with contrast.

      CP02 keeps exact values; CP11 asks the owner to approve a darker token as an exception.

    • R6

      Bangladesh Bank New Website/app/ already holds draft code (27 components, 5 pages)

      Impact: plan could duplicate or ignore work.

      Each checkpoint marks matching files “Verify / rewrite”; its tests decide if the draft stays. Nothing is deleted.

    • R7

      Project CLAUDE.md, agents and skills point to ../01-Bangldesh-Bank-Refactor-Design/, which does not exist

      Impact: agents read no design.

      CP01 changes the path to ../02-Design/.
