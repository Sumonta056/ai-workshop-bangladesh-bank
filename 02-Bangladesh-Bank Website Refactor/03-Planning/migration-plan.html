Prototype HTML → Nuxt 4 SSG Migration Plan

Companion to architecture.md. A 12-checkpoint, build-and-validate path from the single-file design export into a modular, statically-generated Nuxt 4 site — preserving pixel fidelity and the prototype's data-driven pattern.

0 · Guiding Principles

  1. The HTML is the specification. Every color, spacing value, font weight, copy string (en and bn), hover state, and transition is transcribed verbatim. Nuxt conventions yield to pixel fidelity.
  2. SSG only — ssr: true, nitro.preset: 'static'. Build with npm run generate → .output/public/. No backend, no server routes, no runtime fetch.
  3. Preserve the prototype's data-driven pattern — locale dict → typed props → dumb components. The view-model render function becomes useLocale + per-component props.
  4. One responsibility per file. Repeated items extract into their own SFC.
  5. Incremental, verifiable steps. Each checkpoint ends in a green build + visual diff against the original before the next begins.

Prototype Design Pattern (the spec)

  • Single design-tool export using a custom mini-template (sc-for, sc-if, style-hover, {{ }}) — a transcription source, not runtime code.
  • State: view (home | mp | fin | pub | svc) + lang (en | bn). No URLs in the prototype; view switches are in-memory.
  • Content: one T = { en, bn } dictionary; both share an identical shape including a nested pages map for the 4 inner views.
  • View-model: a render function maps locale data + icons + click handlers into flat bindings. Repeated shapes (marketCards, news, modules, services, inner groups/tables) are list-driven.
  • Chrome: utility bar → masthead → sticky nav → ticker → (home | inner) → footer.
  • Inner pages = one shared template driven by L.pages[view] (highlight, link groups, data tables, sidebar).

Target Structure

app/
├─ app.vue                      # <NuxtLayout><NuxtPage/></NuxtLayout>
├─ layouts/default.vue          # utility bar, masthead, nav, ticker, footer + <slot/>
├─ pages/                       # index.vue + mp/fin/pub/svc one-liners
├─ components/{base,layout,home,inner}/
├─ composables/                 # useLocale.ts, useNav.ts
├─ data/                        # routes.ts, icons.ts
├─ i18n/                        # en.ts, bn.ts, types.ts
└─ assets/css/                  # tokens.css, base.css

The 12 Checkpoints

Loop · every CP Build → npm run generate succeeds → Validate (checks below) → Vitest suite green → Live visual QA via Chrome DevTools MCP (console clean, side-by-side diff vs Bangladesh Bank.html) → Commit on green. Never advance on red.
01
Checkpoint 1

Scaffold + tooling baseline

›
Do

Nuxt 4 init, srcDir: app/, ssr: true, nitro.preset: 'static'. TypeScript strict, ESLint + Prettier, Vitest + @vue/test-utils + @nuxt/test-utils. Load Inter + JetBrains Mono via <link> in nuxt.config.ts (same sources as prototype lines 11–15).

Validate

npm run generate produces .output/public/index.html; lint + typecheck pass; one trivial Vitest passes.

Test loop

Smoke test that the dev server boots and fonts resolve (DevTools MCP).

Exit

Empty app builds statically; CI runs the test command.

02
Checkpoint 2

Design tokens + global base CSS

›
Do

Extract palette (#006A4E, #0A3D2C, #F42A41, #E4F1EC, #F4F6F8, borders #E0E4E8…), fonts, max-width 1240px, gutters 40px → assets/css/tokens.css (--bb-*). Port global resets (box-sizing, ::selection, a reset) → base.css.

Validate

No magic duplicates; a token sheet page renders each color/font.

Test

Snapshot test of the token sheet.

Exit

Every recurring value referenced from a token.

03
Checkpoint 3 · highest-value early step

i18n contract (types.ts + en/bn dicts)

›
Do

Transcribe en.ts and bn.ts verbatim from prototype lines ~519–853.

Validate

Both dicts satisfy LocaleContent (typecheck fails on drift); key-count parity test.

Test

Object.keys(en.pages) deep-equals Object.keys(bn.pages) recursively.

Exit

Content layer complete and shape-locked.

Exit

Language state centralized and tested.

Test

Exit

Deployable .output/public/; pipeline enforces quality gates.
