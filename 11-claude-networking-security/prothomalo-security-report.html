2. Findings

F-1   Content-Security-Policy is effectively permissive

HIGH
Category Headers / XSS defense-in-depth · Confidence 9/10 · VERIFIED (observed)
Observed 
content-security-policy: default-src data: 'unsafe-inline' 'unsafe-eval' https: http:;
  script-src data: 'unsafe-inline' 'unsafe-eval' https: http: blob:;
  style-src ...; img-src ...; object-src https: http:; ...
Why it matters A CSP exists, which is good intent — but script-src allows 'unsafe-inline', 'unsafe-eval', plus any https: and http: origin. That permits inline scripts and arbitrary external script hosts, so the policy provides almost no real protection against reflected/stored/DOM XSS. object-src https: http: also allows plugin/embed content from any host.
Exploit scenario If any XSS sink exists anywhere in the app (a comment field, a search reflection, a third-party widget), an injected <script> or inline handler executes unhindered because the CSP whitelists inline + eval + all https/http origins. On a news site that loads many ad/analytics scripts, a single compromised third-party script also runs with no origin restriction.
Recommendation Move to a nonce- or hash-based CSP: drop 'unsafe-inline' and 'unsafe-eval', replace blanket https:/http: in script-src with an explicit allowlist of ad/analytics/CDN domains, set object-src 'none', and remove http: entirely. Roll out via Content-Security-Policy-Report-Only first to catch breakage.

F-2   No HSTS (Strict-Transport-Security header missing)

MEDIUM
Category Transport security · Confidence 9/10 · VERIFIED (observed)
Observed No Strict-Transport-Security header on the HTTPS response. (A 301 http→https redirect exists, but that alone doesn't protect the first request.)
Exploit scenario A user on hostile Wi-Fi types prothomalo.com. The first request goes over plain HTTP. An on-path attacker (SSL-strip) intercepts before the 301 lands and keeps the victim on HTTP, serving a cloned page or capturing the session. HSTS would force the browser to use HTTPS from the start and refuse the downgrade.
Recommendation Add Strict-Transport-Security: max-age=31536000; includeSubDomains; preload (ramp max-age up gradually), then submit to the HSTS preload list. Easy to enable at the Cloudflare edge.

F-3   No clickjacking protection (no X-Frame-Options / frame-ancestors)

MEDIUM
Category Headers / UI redress · Confidence 8/10 · VERIFIED (observed)
Observed No X-Frame-Options header, and the CSP defines child-src but no frame-ancestors directive.
Exploit scenario An attacker embeds prothomalo.com in a transparent iframe over a decoy page, tricking logged-in users into clicking actions (e.g. account/comment actions) they didn't intend — classic clickjacking. Without frame-ancestors/X-Frame-Options, the browser allows framing from any origin.
Recommendation Add frame-ancestors 'self' to the CSP (and/or X-Frame-Options: SAMEORIGIN for older clients). Allowlist any legitimate partner embed domains explicitly.

Why it matters robots.txt is a public file; listing /shell.html and /api/auth/ effectively advertises paths worth attacking. /shell.html is an unusual, attention-grabbing name (often a leftover diagnostic/admin/debug artifact). It was not accessed during this passive review.
Recommendation Confirm what /shell.html is and remove it if it's a leftover. Protect sensitive endpoints with auth/network controls rather than obscurity. Don't rely on robots.txt to hide anything — use it only for crawl control, and gate real secrets behind authentication.

F-6   Missing X-Content-Type-Options: nosniff

LOW
Category Headers · Confidence 9/10 · VERIFIED (observed)
Why it matters Without nosniff, browsers may MIME-sniff responses and execute content as a type the server didn't intend (e.g. treating an uploaded file as script).
Recommendation Add X-Content-Type-Options: nosniff globally.

F-7   Missing Referrer-Policy & Permissions-Policy

LOW
Category Headers / privacy · Confidence 9/10 · VERIFIED (observed)
Why it matters No Referrer-Policy can leak full URLs to third parties via the Referer header; no Permissions-Policy leaves camera/mic/geolocation/etc. unrestricted for embedded content.
Recommendation Add Referrer-Policy: strict-origin-when-cross-origin and a least-privilege Permissions-Policy (deny features the site doesn't use).

INFO
Category Process · Confidence 9/10 · VERIFIED (observed)
Observed /.well-known/security.txt → HTTP 404
Why it matters Researchers who find a bug have no documented, trusted way to report it, which slows responsible disclosure.
Recommendation Publish /.well-known/security.txt (RFC 9116) with a security contact, encryption key, and policy URL.

F-9   Cookie SameSite=None

INFO
Category Cookies · Confidence 8/10 · VERIFIED (observed)
Observed _cfuvid=...; HttpOnly; Secure; SameSite=None (a Cloudflare bot-management cookie).
Why it matters SameSite=None sends the cookie on cross-site requests. It's HttpOnly+Secure and not a session/auth cookie, so risk is low — but verify that any application session/auth cookies use SameSite=Lax or Strict for CSRF defense.
Recommendation Audit application auth cookies (not visible to anonymous visitors) and ensure they're SameSite=Lax/Strict, HttpOnly, Secure.
