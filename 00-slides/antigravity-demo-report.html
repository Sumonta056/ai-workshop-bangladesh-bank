Gemini CLI was retired for consumers on June 18, 2026

The gemini command no longer serves requests on free, AI Pro, or AI Ultra tiers — there was no grace period. Its replacement is Antigravity CLI (the agy command), a Go rewrite sharing the same agent harness as the Antigravity app. Only enterprise (Gemini Code Assist Standard/Enterprise) and paid API keys keep legacy Gemini CLI. Demo agy, not gemini — and check that any pipeline calling gemini hasn't already broken.

01

The shift — from writer to mission controller

Frame the category before the tool. This is not autocomplete; it's delegation.

Antigravity is Google's agent-first development platform (a heavily modified VS Code fork, originally shipped Nov 2025 with Gemini 3, rebuilt as 2.0 at I/O 2026). The premise: the AI isn't predicting your next few tokens — it plans, executes, validates, and iterates on whole tasks while you supervise. Your role moves from typing code to directing agents and reviewing their output.

🖥️ Editor view

A familiar VS Code-style editor with an agent sidebar — for when you want to read, tweak, and stay close to the code.

🛰️ Manager view

A mission-control surface that orchestrates many agents in parallel across workspaces, asynchronously. This is the part that feels new.

🎯 Opening line

"With Antigravity you stop being the person who types every line and become the one who assigns work to a team of agents — then checks what they bring back."

02

Live — one prompt, many agents

The headline demo. Give it a real, multi-part task and narrate the Manager filling up.

In the Manager, a single prompt fans out into a plan, then parallel subagents each take a slice of the work — and you can schedule tasks to run in the background (even overnight). One developer's framing: it lets a single person act like a "full-stack team," keeping frontend, backend, and tests moving at once.

03

The Browser Subagent — it checks its own work

The most demo-friendly feature. Build something with a bug, let the agent catch it live.

Antigravity spins up a real Chrome instance and actually uses the app as it builds it — clicking buttons, filling forms, taking screenshots, reading what happened. If a button doesn't work, the agent sees the failure, debugs it, and fixes it, without you ever opening DevTools. This is what separates "generated code that looks right" from "code the agent verified end-to-end."

04

Artifacts & Walkthroughs — the trust model

This is Antigravity's real differentiator. Don't skip it — it's why people trust autonomous runs.

Because the agents work autonomously, Antigravity makes them show their work. Every task produces Artifacts — verifiable deliverables you review in the Auxiliary Pane instead of reading raw output. The Walkthrough goes further: after finishing, the agent narrates what it built, why it chose certain patterns, and how the files connect — like a senior engineer explaining their PR.

▤ Implementation Plan
Proposed architecture & files. Approve before any code is written.
☑ Task List
Step-by-step checklist with done / pending state as it progresses.
▦ Screenshots & recordings
Visual proof from the browser subagent that flows actually work.
≋ Walkthrough
Narrated explanation of the changes — the reasoning, not just the diff.
🧭 Demo move

Open the Implementation Plan artifact and approve it on screen before letting the agent proceed. It shows the human-in-the-loop checkpoint clearly — and reviewers can approve asynchronously via review gates.

05

Antigravity CLI — the terminal front end

Same agent harness as the app, in your terminal. This is the live replacement for gemini.

Antigravity CLI (agy) is a Go binary — single file, no runtime dependencies, snappier than the old CLI. It runs asynchronous, multi-agent background workflows and shares one architecture with the desktop app, so improvements land everywhere at once. It keeps the features people relied on: Agent Skills, Hooks, Subagents, and Extensions (now plugins).

# Antigravity CLI is available to everyone now; use it with your Google Cloud project
$ agy # start an interactive agent session
$ agy "scaffold a REST API for a todo app, then test the endpoints"

# isolate the agent to the project root, block unauthorized network
$ agy --sandbox "refactor the auth module and run the tests"

# bring your skills/hooks/rules over from the old setup

📦 The Gemini CLI lineage (for the inevitable question)

Gemini CLI proved the terminal was a great agent surface — 100k+ GitHub stars, weekly releases, open source. Google folded it into Antigravity CLI for a "single product built for multi-agent reality." Honest caveats worth stating: agy is closed-source and not at 1:1 feature parity at launch, and the open-source community contributions don't carry into it — a sore point on developer forums.

Models, integrations & security

Close with the practical setup details and the agentic-IDE risks worth naming.

Google-native integrations

Because it's Google: it can authenticate and wire together Sheets, Docs, Drive, and Calendar, and connects natively to AI Studio, Firebase, and Android (export an AI Studio project straight into Antigravity with full context). A demo-able prompt: "build a CRM that pulls leads from my Google Sheet and sends reminders via Calendar."

Security — name these out loud

🪤 Prompt injection

A README or code comment can hide instructions telling the agent to exfiltrate data (e.g. via Markdown image rendering). Scan auto-generated comments for stray outbound URLs; disable Markdown image rendering in previews unless needed.

🧱 Sandbox the agent

Use --sandbox to limit operations to the project root and block unauthorized network requests. Start restrictive.

↩️ Commit early & often

Set incremental commits before the first prompt. If an agent takes a wrong architectural turn, you revert in seconds instead of cleaning up for hours.

😮‍💨 Permission fatigue

A known friction point — don't reflexively approve every prompt. Review what each action actually does, especially for anything irreversible.
