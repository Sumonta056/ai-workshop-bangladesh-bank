How MCP fits in

MCP is not a replacement for protocols — it's a translation layer on top of them.

Key insight: Claude always speaks one thing — JSON-RPC 2.0 over stdio or HTTP. The MCP server is a bridge that translates that into whatever protocol the target system speaks: REST, raw TCP, WebSocket, gRPC, or even a local file read.

MCP's own transport layer

How Claude talks to MCP servers — separate from how MCP servers talk to the world.

Two layers: (1) Claude ↔ MCP server uses JSON-RPC over stdio or HTTP+SSE. (2) MCP server ↔ 3rd party system uses whatever that system speaks. These are completely independent.
Transport 1

stdio (local)

Claude spawns the MCP server as a subprocess. They communicate via stdin/stdout pipes using newline-delimited JSON-RPC 2.0. No network involved.

Claude → MCP stdin: {"jsonrpc":"2.0","id":1, "method":"tools/call", "params":{"name":"query", "arguments":{"sql":"SELECT *"}}} MCP stdout → Claude: {"jsonrpc":"2.0","id":1, "result":{"rows":[...]}}
Used by: Memory, Filesystem, Playwright, PostgreSQL, GitHub (local)
Transport 2

Streamable HTTP

MCP server runs independently or in the cloud. Claude sends HTTP POST requests. Server can stream back responses via SSE. Enables remote MCP servers.

POST https://mcp.example.com/mcp MCP-Protocol-Version: 2025-06-18 Content-Type: application/json {"jsonrpc":"2.0","id":1, "method":"tools/call", "params":{...}} ← HTTP 200 or SSE stream
Used by: Sentry MCP, hosted Figma MCP, remote services
